# BlueFishSerial 串口调试助手

基于 C++/Qt5 的串口调试工具。从零实现：通信逻辑与界面分离，串口 I/O 运行在独立工作线程，
支持文本 / HEX 收发、字节计数与可操作的中文错误提示。

- **语言 / 框架**：C++11 / Qt 5（Qt Widgets、QSerialPort、QThread）
- **构建方式**：qmake（`BlueFishSerial.pro`）
- **规模**：5 个 C++ 源文件，约 470 行（不含 `.ui`）

## 功能

- **串口枚举**：启动时读取系统可用串口与标准波特率列表
- **打开 / 关闭**：按钮状态由**实际打开结果**驱动，而非点击翻转
- **打开失败提示**：按 `QSerialPort::SerialPortError` 映射为可操作的中文提示
  （找不到设备 / 被占用 / 打开失败 / 参数不支持 / 兜底 `errorString()`）
- **收发**：文本模式与 HEX 模式，由同一个复选框同时控制**显示格式**与**发送解析**
- **HEX 发送校验**：仅允许 `[0-9A-Fa-f]`，忽略空白；长度必须为偶数；
  非法输入给出明确提示并**拒绝发送**（不会静默发出空数据）
- **发送结果反馈**：`write()` 实际写入字节数与期望不一致时提示失败，不累加计数、不显示发送记录
- **字节计数**：RX / TX 分别累计并显示
- **清空**：清空收发区并将计数归零

## 目录结构

```
BlueFishSerial.pro     qmake 工程
main.cpp               程序入口
widget.h/.cpp/.ui      界面层：串口枚举、收发显示、计数、按钮状态
serialcomm.h/.cpp      串口层：打开/关闭、收发、错误映射（运行于工作线程）
```

两层的依赖是单向的：`Widget → SerialComm`。

## 实现要点

1. **线程模型**
   `SerialComm` 通过 `moveToThread` 移入工作线程，界面与它之间全部用信号槽通信（跨线程自动排队）。
   打开结果通过 `openS` / `openF` 信号回主线程后再修改控件 —— **不在工作线程碰 `ui`**。

2. **对象所有权**
   `QThread` 有父对象，由父对象回收；`SerialComm` 无父对象（`moveToThread` 的硬性要求），
   通过 `QThread::finished → QObject::deleteLater` 回收。

3. **配置应用时机**
   端口名 / 波特率只记录在 `SerialComm::Config` 中，统一在打开前应用 ——
   因为 `QSerialPort` 的端口名必须在 `open()` **之前**设置，打开后再改无效。

4. **数据与显示分离**
   接收到的原始字节只读，不做任何原地修改；显示时才按当前模式格式化为 HEX 或文本。
   **绝不用"给眼睛看的字符串"覆盖"给机器用的字节"。**

5. **发送结果反馈**
   `write()` 的返回值会与期望字节数比对，不一致时通过 `writeNote` 信号回主线程：
   提示失败、**不累加计数、不显示发送记录** —— 界面不会"假装发送成功"。
   失败路径已用故障注入（临时置 `n = -1`）验证。

## 如何构建

1. Qt Creator 打开 `BlueFishSerial.pro`（需安装 **QtSerialPort** 模块）
2. 构建并运行

命令行：

```sh
qmake && make        # Windows + MinGW: qmake && mingw32-make
```

## 已知限制

1. **无断线重连**：运行中设备断开 / 端口消失不会自动恢复，`QSerialPort::errorOccurred` 未处理。
2. **串口参数固定 8N1**：8 数据位、无校验、1 停止位、无流控，界面只能改端口名与波特率。
3. **串口列表只在启动时枚举一次**，不支持热插拔刷新。
4. **接收区按"一次 `readyRead` 一行"追加**，不做时间戳与跨包拼接
   （对调试二进制协议来说便于观察分片，但对长文本不够友好）。
5. **不含协议解析与 CRC** —— 有意留白，属于后续阶段的内容。
6. **暂无可自动运行的测试**，仅有下面的手动测试清单。
7. **发送显示的时序前提**：`sendArray_` 与复选框状态是"发送时刻"的上下文，回调中读取存在
   极小窗口（实测远小于人手连点间隔，正常操作撞不上）。若以后加入自动发送 / 高频轮询，
   应改为把数据作为信号参数传回，而不是读共享成员。
